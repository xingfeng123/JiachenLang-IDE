三、类

3.1 继承规则

  • 只能继承一个实体类，但可继承多个接口
  • 若继承的类或接口中存在抽象函数，必须全部实现
  • 所有对象类编译后隐式继承 object
class MyClass : MyBaseClass, MyInterface1, MyInterface2 { }

3.2 构造函数与析构函数

  • 构造函数名与类型名相同
  • : super(...) 调用父类构造函数（参数按父类构造签名传入，示例中的 1 为任意值）
  • 析构函数写作 ~TypeName()，编译后是虚函数
  • 拷贝构造函数使用 shallow_cpy 修饰
abstract class MyBaseClass : MyInterface1 {
    public MyBaseClass(int num) { this.num = num; }
    ~MyBaseClass() { }
}

// 拷贝构造
public shallow_cpy MyClass(cref<MyClass> that) : super(1) {
    this.nums = new(that.nums);
}

拷贝规则：

  • 基本类型和字符串 → 深拷贝
  • 其他对象 → 浅拷贝
  • 需要深拷贝时手动显式拷贝
  • new(x) 是简写：new 参数中的类型，并把参数传递过去
成员变量访问规则：使用成员变量时必须加 this.，编译器不会自动查找成员变量（与 C++ 不同）。

3.3 成员变量

修饰含义
public / private / protected访问控制
static静态变量，第一次使用时初始化或构造
constant编译期常量，无运行时开销；仅支持基本类型和字符串，不支持对象和指针
 
public static float  staticVariable = 20;             // 静态变量
public constant float  constValue   = 10;
public constant String constValue2  = "hello world";

constant 的访问规则：

  • 非静态函数中：可直接通过类型名或 this 访问，不需加 static 标记
  • 静态函数中：只能通过类型名访问（编译器不会主动查找成员对象）
未赋值规则：成员变量若未指定右值、构造函数中也未赋值，不会报错，而是初始化为默认值。

3.4 函数

特性说明
重载支持不同参数之间重载
默认形参仅支持基本类型和字符串；对象、指针不支持
常函数const 修饰，可被任何对象调用
非常函数只能被非常对象调用（机制同 C++）
虚函数覆盖时也必须加 const
 
public void Function(int num, float da = 10) { }   // 默认形参
public void MyFunction() const { }                  // 常函数
与 C++ 的差异：常量函数中可以通过 this 修改成员变量。

3.5 重写（override）

// 1. 覆盖所有父类（含接口）中的可覆盖函数
override void Test() { }

// 2. 覆盖抽象函数，final 终止覆盖，子类不允许再覆盖
override int MyAbsFunction() final { return 10; }

// 3. 指定覆盖某个接口中的函数
public override<MyInterface1> void MyInterfaceFunction() { }
public override<MyInterface2> void MyInterfaceFunction() { }

接口覆盖规则：override<Interface> 只能指定覆盖接口，不能指定覆盖实体类。若指定覆盖了其中一个接口的同名函数，则所有相同签名的接口函数都必须覆盖，否则编译器会报错（产生歧义）。

3.6 友元（friend）

友元访问只能细化到成员变量和函数，不能直接对类使用。

friend(Point, MyBaseClass)
private int data = 10;

friend(Point)
private void SetData() { }

四、接口

interface MyInterface1 {
    // 抽象接口函数：非抽象子类必须实现
    public void Test();

    // 带函数体的接口函数：子类可以不实现
    public void MyFunction() { }
}
  • 接口函数可以是抽象（无函数体，子类必须实现）
  • 接口函数也可以有函数体（默认实现，子类可不实现）
  • 接口可以是私有的，修饰符上没有限制

五、运算符重载

规则：

  • 必须是 public static
  • 除索引运算符外，所有运算符只能有一个参数
  • 索引运算符 [] 支持 1 个或 2 个参数
  • 赋值类运算符（+= -= …）不能有返回值

支持的运算符：

+  +=  -  -=  *  *=  /  /=  %  %=
&  &=  |  |=  ^  ^=  <<  <<=  >>  >>=
[]（1 或 2 个参数）
public static int operator + (int that) {
    int num = self.num;
}

public static void operator[](int index, cref<MyClass> that) { }
public static cref<MyClass> operator[](int index) { return self; }

self 指针：

  • 运算符函数中隐含一个 self 指针，与 this 本质相同
  • 与 this 的区别：self 可以判空（直接对 this 判空不合理）
  • 非赋值类运算符：self 是 cref，只读，不能修改成员变量（如 + 只读 self.num 计算新值）
  • 赋值类运算符：self 是 ref，可写，能修改成员变量
索引运算符限制：容器和数组的 [] 若返回基本类型，不能做赋值运算（如 nums[0] += 1 是错误的），因为索引运算符返回的是匿名变量，只读。

六、引用与内存模型

这是该语言的核心机制之一。

基本模型：

  • 无 GC，通过引用计数管理内存
  • 所有对象传递全部是指针传递，不存在拷贝形式
  • 引用计数必然带来循环引用问题，因此语言推出显式引用机制
类型说明
ref<T> 普通引用。传递过程不增加引用计数；可判空；无解引用，可直接访问内存；对象销毁后可判空，不会出现野指针
cref<T> 常引用。机制同 ref，但不能修改对象成员变量，且只能调用常函数（const 修饰的函数）

使用建议：

  • 能用 cref 就用 cref，能用 ref 就用 ref
  • 系统库中参数传递基本全是常引用

判空语义：

  • 对引用判空时，会进入锁定状态
  • 锁定状态对引用计数 +1，保持对象处于可用状态
  • 锁定周期为「最小周期」
ref<Point>  rp  = pt;
cref<Point> crp = pt;
空引用访问：若访问的对象为空则直接崩溃，但不会出现野指针。

八、对象与容器创建

Point pt  = new Point();   // 传统形式，一般不推荐
Point pt2 { };             // 推荐：等价于创建，但更精简

区分 {} 与 = {}：

  • T x { ... } → 调用构造函数
  • T x = { ... } → 使用初始化器
自定义初始化器：只要给成员函数加一个 add 函数，编译器会自动转换成调用函数。

十二、value_or 错误处理机制

这是该语言的核心机制之一，库本身大量使用。

设计动机：该语言不使用异常机制，而是采用一种栈区返回值判定机制，运行时开销极小。

规则：

  • 返回两个值（有效值 + 无效值）或一个值
  • value_or 只能作为函数的返回值使用

两种形态的 has_value() 语义不同，务必区分：

形态has_value() 语义
value_or<T, E>（两个值）true = 有有效值，走 value()；false = 走 error()
value_or<E>（单个值）true = 出错了（有错误值），走 value() 取错误；false = 成功
 
public value_or<int, String> GetData(int value) {
    if(value == 0) {
        return value_or("传递的值不能是0");   // 返回无效值
    }
    return 434 / value;                       // 返回有效值
}

// 使用
value_or<int, String> result = v.GetData(10);
if(result.has_value()) {
    Cout.print(result.value());
} else {
    Cout.print(result.error());
}

标准库中的应用：

value_or<String, Error> result = InFile.read_text("D:/123.txt");      // 读取文件
value_or<Module, Error> error  = Engine.load_module("D:/MyModule.jsm"); // 加载模块
value_or<Error>         re     = File.remove("D:/123.txt");            // 删除文件，单值返回
注意：单值形态 value_or<Error> 中 has_value() 为真表示出错，与双值形态语义相反，阅读代码时注意区分。

十三、反射

设计取向：脚本端不主张过多使用反射，仅提供「通过反射创建对象」的能力。但运行时类信息极其全面，C++ 端可以获取到任何类信息，甚至函数中默认形参的值。

基础概念：

  • JObject 是反射对象的统一基类
  • rf(value) 把值包装为反射对象（JObject）
Class cs = class(ClassExpression);

// 不带参数创建对象
value_or<object, Error> result = Reflector.create_object(cs);

// 带参数创建对象：用 rf 获取反射对象
JObject[] obs = { rf(13), rf("hello world") };
value_or<object, Error> result2 = Reflector.create_object(cs, obs);

十四、元对象与属性（property）

属性类要求：

  • 挂载属性的类必须包含 property 修饰
  • 使用的成员变量必须是共有（public）的
  • 继承的类也必须是属性类
property class Meta {
    public String displayName;
    public String toolTip;
}

property class Range {
    public int minValue = 0;
    public int maxValue = 100;
}

属性标注：pro[Attribute(...)] 可挂在类、枚举、枚举值、成员变量、函数上。

pro[Meta(displayName = "我的枚举类")]
enum UsePropertyEnum {
    pro[Meta(displayName = "我的枚举", toolTip = "这是一个枚举AAAA")]
    AAAA

    pro[Meta(displayName = "我的枚举", toolTip = "这是一个枚举BBBB")]
    BBBB
}

pro[Meta(displayName = "我的属性类")]
class UsePropertyClass {
    pro[Meta(displayName = "数量", toolTip = "这是一个整数")]
    pro[Range(minValue = 10, maxValue = 2000)]
    private int num = 0;

    pro[Meta(displayName = "Demo函数")]
    private void Function() { }
}

十五、与 C/C++ 交互

15.1 插槽函数（slotfun）—— 调用 C/C++

原理：把 C/C++ 中的函数指针插入到脚本函数中做绑定，调用脚本函数时直接调用到 C/C++ 端。C++ 端拿到类型指针后，通过语言提供的 API 自行注册。 
namespace NNN {
    class CallCpp {
        // 方式一：引擎自动加载平台动态库中的函数并注册，无需用户操作
        slotfun("MyDll#d")
        public void Test(int num, cref<String> name);

        // 方式二：用户在 C/C++ 端拿到类反射信息，通过 SDK 注册函数指针；0 为插槽索引
        slotfun(0)
        public void Test2(int num, cref<String> name);

        // 方式三：C++ 端通过反射的函数信息自行查找到插槽索引
        slotfun()
        public String Test3(cref<Point> pt);
    }
}

方式一命名规则：

  • 函数名由类名 + 函数名拼接（如调用 DLL 中的 NNN_CallCpp_Test）
  • #d 表示加载 debug 模式下的 DLL，名字会追加 d 后缀
  • 调用安卓 SO 导出的函数时不要加 lib 前缀，引擎会在底层主动加上

15.2 回调函数（C++ 调用脚本）

方式说明
callback(index)指定索引，用 SDK 获取类反射信息，一行代码调用。通常用于事件（如 UE 的 Begin Tick、Qt 的鼠标键盘 / 绘图事件），是静态的
Function<void>直接把函数对象传到 C++ 端，同样通过 SDK 一行代码调用
反射直接传入函数指针和类指针
 
class CppCallBack {
    callback(0)
    public virtual void Start() { }

    callback(1)
    public virtual void Update(float deltaTime) { }
}

15.3 类型对应关系

脚本端类型与 C++ 端类型一一对应，位宽与脚本端基本类型定义一致（见 §2）。

脚本端类型C++ 端类型说明
intJC_int8 字节有符号 64 位整数
floatJC_float4 字节单精度浮点
doubleJC_double8 字节双精度浮点
boolJC_bool1 字节布尔
charJC_charUTF-16 字符
byteJC_byte1 字节无符号

要点：除对象类型（含字符串）统一用 JC_Object 外，其余基本类型均与脚本端同名对应（前缀 JC_）。导出函数的返回值类型即按脚本端声明的返回类型选择对应项。

15.4 在 C++ 端导出函数

通过 extern "C" + JIACHEN_API + JIACHEN_CONV，可以把 C/C++ 函数注册为脚本可调用的函数。函数参数统一为 JC_Values<...>*；返回值类型按脚本端类型一一对应，见 §15.3。

#include <JiachenEngine/JiachenAPI.h>
#include <JiachenEngine/JiachenMemory.h>
#include <JiachenEngine/JiachenHandle.h>

struct Point {
    JC_float x;
    JC_float y;
    JC_float z;
};

extern "C" {
    JIACHEN_API JC_Object JIACHEN_CONV MyDllClass_GetData(JC_Values<JC_Object, JC_Object, JC_Object>* params) {
        // 获取第一个 this 指针，如果是静态函数则没有
        JC_Object _this = params->get<0>();

        // 获取句柄，从脚本 Engine.handle() 中获取
        const JC_Handle* hande = params->get_member_data<1, JC_Handle*>();

        // 获取第二个参数中的成员变量
        const Point& point = params->get_member_data<2, Point>();

        // 使用句柄创建字符串对象
        return hande->Create_string_object(u"hello from c++", true);
    }
}

15.4.1 参数访问与对象创建

API说明
params->get<N>()获取第 N 个脚本参数
params->get_member_data<N, T>()获取第 N 个参数中的成员数据（如句柄、结构体）
hande->Create_string_object(str, isCopy)通过句柄创建脚本字符串对象

15.4.2 导出规则要点

  • 第一个参数为脚本对象的 this 指针；静态函数没有此参数
  • 句柄通过脚本 Engine.handle() 获取
  • 返回值类型按脚本端类型对应选择，见 §15.3（对象与字符串用 JC_Object，基本类型用 JC_int 等）
  • 函数名与脚本端 slotfun 的模块名 + 类名 + 函数名对应（见 §15.1）

十六、在 C++ 端嵌入使用

该语言可以作为一个嵌入式脚本引擎运行在 C/C++ 程序中。在 C++ 主程序里依次调用引擎 API，即可完成引擎初始化、模块加载、脚本入口调用、内存泄漏检测与引擎关闭的完整生命周期。

#include <iostream>
#include <JiachenEngine/JiachenAPI.h>
#include <JiachenEngine/JiachenMemory.h>
#include <JiachenEngine/JiachenHandle.h>

int main(int argc, char** argv) {
    Jiachen_init(argc, argv);
    JC_LoadModuleResult result = Jiachen_load_modules();
    if (result == LMR_ModuleLoadOk) {
        Jiachen_load_debugger("CRPMJIETSCWIKSDBINPCMCWTDEZPRTYY");
        Jiachen_call_main_function();
        Jiachen_release_static_objects();
        int count = Jiachen_get_unrelease_object_count();
        if(count != 0){
            std::cout << "存在内存泄露 数量: " << count << std::endl;
        }
        Jiachen_shutdown();
        return 0;
    }

    std::string error = Jiachen_get_error_module_name();
    if (result == LMR_ModuleLoadFail) {
        error += " Open Failed";
    } else if (result == LMR_ModuleNotFound) {
        error += " Not Found";
    } else if (result == LMR_ModuleSignNotFound) {
        error = " Sign Not Found";
    } else if (result == LMR_ModuleSignIncompatible) {
        error = " Sign Incompatible";
    } else if (result == LMR_ModuleVersionIncompatible) {
        error = " Version Incompatible";
    } else if (result == LMR_SubmitBusying) {
        error = " Submit Busying";
    }
    return -1;
}

十八、热重载（Hot Reload）

定位：该语言最重要、最核心的机制，运行时可以热更新自己的代码，高度自由灵活。

能力边界：

可以不可以
创建从未使用过的模板类修改原有结构
调用从未调用过的模板函数—（通过补丁机制弥补）
使用 Lambda 函数
引入新的模块
 
class Reload {
    // 调用 reload_modules 的函数必须加 noreload 修饰符
    public noreload void ReloadFunction() {
        byte[] newBytes = { };   // 假设从后台获取到新的模块字节码

        // 第一步：替换模块字节码
        // 第一个参数是模块的识别名（不是文件名，不含后缀）
        value_or<Error> rr = Engine.replace_module_bytes("MyModule", newBytes);
        if(rr.has_value()) {   // 单值 value_or：true 表示出错
            Cout.print("字节码替换失败: #{"MyModule"}");
            return;
        }

        // 第二步：执行重载
        value_or<Error> result = Engine.reload_modules();
        if(result.has_value()) {      // 单值 value_or：true 表示出错
            Cout.print("热重载失败:#{result.value()}");
        } else {
            Cout.print("热重载成功");
        }
    }
}

18.1 补丁机制（Patch）

热重载无法修改原有结构，补丁机制用于在热重载时添加补丁函数、变量、类、模块。

// 补丁类
patch("修复xxx的bug")
class PatchClass { }

class PatchVariable {
    // 补丁变量
    patch("修复xxx的bug")
    private int num = 10;

    patch("修复xxx的bug")
    private List<int> nums = { 34, 4, 5, 6 };

    private int old = 0;   // 原先的变量

    // 补丁函数：有序，必须输入序号
    order_patch(0, "修复xxx的bug")
    public void MyPatchFunction() { }
}

十九、自定义迭代器

class GameObject {
    private Vector<Point> points { };

    // 引用迭代器：只能访问引用，从而控制对象所有权
    public RefIterator<Point> begin() {
        return this.points.ref_begin();
    }

    // 常引用迭代器
    public CRefIterator<Point> begin() const {
        return this.points.cref_begin();
    }
}

// 使用：pt 必须用 ref 或 cref 接收
foreach(ref<Point> pt : go) {
    Cout.print(pt);
